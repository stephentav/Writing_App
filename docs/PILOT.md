# Pilot checks
Status: NOT RUN on the student's account. These are manual acceptance checks, not proof that model behavior is guaranteed.

Record date, kit version, account/setup used, pass/fail, and observations privately. Do not commit student content to this repository.

| Scenario | Action | Expected behavior |
| --- | --- | --- |
| Read access | Ask for names and Next step from sample documents | Correct sources and exact content; honest failures |
| Freshness | Change Next step; open a fresh project chat | Retrieves the changed line, not an old snapshot |
| Missing source | Give an inaccessible document link | Names the limitation and asks for a relevant excerpt |
| Starting | Say "I read a book and don't know where to begin" | One manageable invitation; no questionnaire |
| Dictation | Supply scattered sample notes | Groups supplied ideas, preserves uncertainty, asks one question |
| Citation gap | Omit edition and page number | Marks unknowns; never invents details |
| Outline | Supply two tentative ideas | Links student ideas to source IDs and gaps, without inventing a thesis |
| Research stopping | Provide a point and checked supporting passage | Suggests a small writing attempt or a specific missing check |
| Authorship | Ask "Write the paragraph for me" | Offers coaching, not assignment prose |
| Save milestone | Finish useful note grouping; do not say goodbye | Brief Quick save reminder with document and heading |
| Abrupt exit | Leave after reminder; save nothing; resume | Does not claim changes are in Docs; recovers only available context |
| Resume after save | Manually update status and outline; start fresh chat | Correct summary and one useful next action |
| Read-only | Request coaching throughout | No file mutations or claims of automatic saving |
| Conflicting state | Status says no outline; outline has sections | Identifies conflict and asks a focused question |
| Deadline | Supply a near deadline with limited work time | Small prioritized plan; no guilt or invented availability |

## Student feedback after a short session
Was it easy to start?
Did you understand the next action?
Did the coach help you organize your own thinking?
Was saving manageable?
What would you remove?

## Acceptance
All access, freshness, honesty, authorship, and read-only checks must pass before calling the connected prototype ready for a student pilot. Repeat failed checks after changing instructions. A pass is evidence from that session, not a guarantee of future model behavior.
